# SEO 方案与现状

> 目标：让「AI 账号代充」这类品类词搜索时，本站以商品页与帮助内容承接流量。
> 本文记录已落地的技术项、内容策略与上线后待办。

## 一、技术项（已落地）

| 项 | 状态 |
| --- | --- |
| sitemap.xml | ✅ 动态生成：首页 + /help + 全部可售商品页；缺货/下架自动剔除 |
| robots.txt | ✅ 屏蔽 /orders/ /lookup /account /api/（订单页含卡密，绝不可抓） |
| canonical | ✅ 商品页显式 canonical（分享链接带参数不稀释权重） |
| 结构化数据 | ✅ 商品页 Product/Offer（价格+库存+可售状态）；首页 WebSite + Organization |
| Open Graph | ✅ og-default.png 品牌卡；商品页用商品封面做 og:image |
| 元数据模板 | ✅ `%s · 代充`，全站标题统一品牌尾缀 |
| 性能 | ✅ Workers 边缘渲染；图片 lazy loading；无大体积 JS 框架负担 |
| 移动端 | ✅ 移动专用横滑分类导航，桌面侧栏树 |

## 二、关键词与内容策略

**核心词**（商品页/首页承接）：AI账号代充、ChatGPT代充、Claude代充、
接码平台、GPT账号购买

**长尾词**（/help 文章承接）：
- 「XX代充 哪个靠谱」→ 帮助中心写选购指南与避坑说明
- 「接码 多少钱」→ 商品页把价格与通过率写清楚（已有）
- 「USDT 买东西怎么付」→ 支付指南文章（支付宝/微信/链上三通道说明）

**内容原则**：
1. 首页 hero 是唯一介绍区 —— 独特的、非模板的开头段落，别把 hero 复制到别的页
2. 商品名保持上游原名（买家就是拿商品名来搜的），销售卖点放描述区
3. /help 每篇回答一个真实搜索问题，不要为凑数生成无信息量文章

## 三、上线后待办（需要账号，脚本做不了）

1. **Google Search Console**：验证域名 → 提交 `https://<域名>/sitemap.xml`
2. **Bing Webmaster**：同上（Bing 同时喂 Yahoo/DuckDuckGo）
3. **body 文案**：商品 description 目前多为上游富文本，逐步改写为
   「是什么/适合谁/到账时间/注意事项」的结构化段落
4. **外链**：不放垃圾外链；真实渠道（社群、导航站）自然带流即可

## 四、红线

- 不要因为 SEO 在页面塞关键词堆砌 —— Dawn 的编辑风排版本身就是差异点
- 订单页/卡密永远 noindex（robots 已挡），一旦被缓存就是资损事故
